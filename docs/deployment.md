# 公開と iPhone での使い方

## GitHub Pages への公開

このフォルダには GitHub Pages 用の自動公開設定 `.github/workflows/pages.yml` を含めています。ノートを GitHub に保存する設定ではありません。公開するのはアプリのコードと初期サンプルです。

1. GitHub にログインし、アプリのリポジトリを作成します。名前の例は `folio-notes` です。公開範囲は利用者が決めます。公開リポジトリの場合、ソースコードは誰でも閲覧できます。
2. このプロジェクトを `main` ブランチに登録します。`node_modules`、個人のバックアップ JSON、秘密情報を登録しないでください。通常の Git 操作では `.gitignore` がビルド生成物などを除外します。
3. リポジトリの **Settings → Pages** を開き、**Build and deployment → Source** を **GitHub Actions** にします。
4. **Actions** で **Publish Folio to GitHub Pages** を開きます。`main` への反映で起動します。必要なら **Run workflow** を押します。
5. `build` と `deploy` が完了すると、Pages の URL が表示されます。この URL が利用開始用のアプリ URL です。

GitHub への接続とリポジトリ作成がまだ終わっていない環境では、公開 URL はありません。コードが手元にあることと、インターネットへの公開完了は別です。非公開リポジトリからの Pages 利用可否は GitHub の契約・設定にも依存するため、Settings → Pages の案内を確認してください。[GitHub Pages の公式案内](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages)

`vite.config.ts` は相対パスでアセットを出力します。manifest の `start_url` / `scope`、Service Worker のリソースも相対パスにしているため、`https://ユーザー名.github.io/リポジトリ名/` の配下に配置できます。アプリ内画面はサーバー上の別ページを要求しません。ブックマークには末尾 `/` のアプリ URL を使ってください。

## iPhone 15 のホーム画面へ追加

1. iPhone の **Safari** で公開した HTTPS のアプリ URL を開きます。
2. 初回読み込みが終わるまで、インターネットにつないでおきます。
3. Safari の **共有** ボタンを押します。
4. 一覧から **ホーム画面に追加** を選びます。見つからなければ一覧を下へスクロールします。
5. 名前を「Folio」にして **追加** を押します。
6. ホーム画面のアイコンから開きます。試しにノートを作り、「保存済み」の表示後に閉じ、もう一度開いて内容を確認します。
7. ホーム画面から使い始めた後、その環境からバックアップを保存してください。

Safari とホーム画面アプリの保存領域の扱いは iOS のバージョンや起動方法によって異なることがあります。大切なノートが既にある場合、追加前にバックアップを書き出し、ホーム画面から開いた環境でも内容を確認してください。別の環境に見える場合は、バックアップを復元して移行します。

## オフラインで使う

初回のオンライン読み込みと Service Worker の準備後、アプリの画面と編集機能をオフラインで使えます。ノートの保存先は同じ端末の IndexedDB です。インターネット上の画像やリンク先まではオフライン化しません。

開発用の `npm run dev` では Service Worker を登録しません。PWA を確認する場合は本番ビルドを使います。HTTPS の公開サイト、またはブラウザが安全なローカル環境として扱う `localhost` / `127.0.0.1` で利用してください。PC の `http://192.168...` を iPhone から開く方法では、安全な環境が必要な PWA・クリップボード機能が制限されます。

## アプリの更新

新しいコードを `main` に反映すると自動公開します。利用中の Service Worker は、その版の画面 HTML と JS・CSS を組にしてキャッシュから提供します。オンライン中も未適用の新しい HTML だけに切り替わらないため、画面とコードの版が混ざることを防ぎます。

アプリを開いて更新通知が表示されたら、保存完了を確認して反映します。新しい版の全ファイルの準備が終わってから、待機中の Service Worker を明示的に有効にして再読み込みします。更新で IndexedDB のノートを削除する処理はありません。Service Worker は画面用ファイルだけをキャッシュし、保存処理には介入しません。

公開 URL や独自ドメインを変更する前には、必ずバックアップを作成してください。ホストやポートが変わると、別の保存領域になります。

## 公開後の確認

- PC と iPhone の両方で起動し、ノート作成・再読み込み・表編集・画像取り込みを試します。
- ホーム画面から起動し、縦横とキーボード表示時の操作を確認します。
- オンラインで起動した後、機内モードで再起動・編集・保存・再表示を確認します。
- バックアップを保存し、別の検証用ブラウザで復元します。日常のノートを使った破壊的な検証は避けてください。
- Safari の通常貼り付け、画像のファイル読み込み、範囲選択コピーを試します。

この手順書の存在は iPhone 実機での検証完了を意味しません。実施済みの項目はテスト記録で区別します。
